# تشغيل حسابات SMS المتعددة المُدارة

يدعم كل Tenant في Wa Savana عدة حسابات SMS. المفتاح التشغيلي للمحادثة هو:

```text
tenant_id + sms_account_id + contact_number
```

لذلك يمكن لبوابتين إرجاع `message_id` أو `ussd_id` نفسه دون اختلاط، كما لا يمكن
لـWebhook الخاص بحساب تحديث رسائل أو طلبات USSD لحساب آخر.

## الإعداد

اضبط في بيئة خادم Wa Savana:

```dotenv
SMS_GATEWAY_CALLBACK_BASE_URL=https://wa.example.com/api/integrations/sms-gateway/events
SMS_GATEWAY_PROVISIONING_SECRET=<shared-random-32-byte-secret>
SMS_GATEWAY_ALLOW_TENANT_MANUAL_CONFIG=false
SMS_WEBHOOK_RATE_LIMIT_PER_MINUTE=1200
SMS_HISTORY_SYNC_INTERVAL_MS=120000
```

إذا كانت بوابة SMS داخل شبكة خاصة، أضف أسماء DNS الدقيقة التي يديرها المشغّل فقط:

```dotenv
SMS_GATEWAY_PRIVATE_HOST_ALLOWLIST=sms.dev.example.com
```

اترك هذا المتغير فارغًا للبوابات العامة؛ لا تُستخدم wildcards ولا قيم يحددها المستأجر.

يجب أن تكون قيمة `SMS_GATEWAY_PROVISIONING_SECRET` مطابقة للقيمة في خادم
SMS Gateway، ومختلفة عن مفاتيح العملاء وكل أسرار النظام الأخرى. يرسل خادم البوابة
طلب التهيئة إلى:

```text
POST https://wa.example.com/api/integrations/sms-gateway/provision
```

يدخل مشرف SMS Gateway بريد مالك حساب Wa أو `tenant_id`، ويختار حساب البوابة
والجهاز والشريحة ثم ينفذ الربط. ينشئ Gateway مفتاحًا مخصصًا محدودًا للربط، مستقلًا
تمامًا عن مفتاح API العام للعميل، ويرسل الطلب بتوقيع HMAC ومعرف منع تكرار. يضبط Wa
الـWebhook ويفحص الاتصال ثم يظهر الحساب للمستخدم تلقائيًا.

توقيع طلب التهيئة هو
`v1=HMAC_SHA256(secret, timestamp + "." + delivery_id + "." + raw_body)` في
`X-Savana-Signature`، مع إرسال القيم نفسها في `X-Savana-Timestamp` و
`X-Savana-Delivery-Id`. يجب التحقق من البايتات الخام قبل تحليل JSON، ورفض إعادة
استخدام `delivery_id` مع محتوى مختلف.

بيانات كل حساب مُدار هي:

- اسم فريد داخل الـTenant.
- رابط SMS Gateway عام وآمن يظهر فقط داخل نافذة «API والربط».
- مفتاح ربط داخلي مستقل، يخزن مشفرًا بـ`CRYPTO_KEY` ولا يعاد للمستخدم.
- مفتاح API العام الحالي لحساب Gateway يُسترجع عند الطلب من البوابة ولا يخزنه Wa؛
  لذلك يظهر التدوير فورًا، ويبقى متوافقًا مع تكاملات العميل الحالية.
- أجهزة افتراضية اختيارية ومنفذ SIM اختياري عند تحديد جهاز واحد.
- أسماء الجهاز والشريحة المفهومة للمستخدم دون كشف المعرّفات التقنية.
- حالة التفعيل وعلامة الحساب الافتراضي.

يدعم Tenant واحد عدة حسابات SMS؛ كل حساب Gateway يُربط بـTenant واحد، بينما يمكن
لعدة حسابات Gateway مستقلة أن ترتبط بالـTenant نفسه. التدوير والإلغاء يتمان من لوحة
إدارة SMS Gateway مع سجل تدقيق ومنع تكرار.

يظل الإعداد اليدوي مسار توافق طارئ فقط عند ضبط
`SMS_GATEWAY_ALLOW_TENANT_MANUAL_CONFIG=true`، ولا ينبغي تفعيله في الإنتاج المعتاد.

إن لم يحدد المرسل `sms_account_id` يستخدم الحساب الافتراضي داخل الـTenant نفسه فقط؛
لا يوجد حساب عام أو fallback مشترك بين العملاء. الرد من محادثة SMS
يستخدم دائمًا الحساب الذي استقبل المحادثة، ولا ينتقل تلقائيًا إلى حساب آخر.

## دورة الرسالة

1. يحجز Wa Savana تكلفة `sms.text` بمفتاح منع تكرار.
2. يرسل الطلب إلى حساب SMS المختار عبر HTTPS بعد التحقق من DNS وتثبيت عنوان IP.
3. عند قبول البوابة يثبت الخصم ويحفظ الرسالة باسم الحساب.
4. تستقبل حالات الإرسال والرسائل الواردة عبر Webhook موقع لكل حساب.
5. يحدث الصندوق الموحد مباشرة عبر SSE، مع منع تكرار `delivery_id`.
6. تطابق مهمة دورية سجل الرسائل بالـAPI ذي الصفحات لاستعادة أي Webhook فائت، ثم
   تستورد الصفحات القديمة تدريجيًا دون تعطيل الرسائل الجديدة.

## API الخارجي من Wa Savana

يستخدم العميل مفتاح Wa Savana الظاهر في صفحة إعدادات API، وليس مفتاح SMS Gateway:

```http
POST /api/v1/sms/messages
X-API-Key: <wa-savana-api-key>
Idempotency-Key: order-2026-000123
Content-Type: application/json

{"recipient":"218912345678","message":"Your order is ready","sms_account_id":12}
```

`sms_account_id` اختياري؛ عند حذفه يستخدم Wa الحساب الافتراضي. لا يقبل هذا المسار
معرّفات الأجهزة أو منفذ SIM من النظام الخارجي، لأن الإدارة تتحكم في التوجيه. يمكن
قراءة الحسابات المنطقية عبر `GET /api/v1/sms/accounts`، وحالة رسالة مقبولة عبر
`GET /api/v1/sms/messages/{message_id}`. عند ضبط Callback URL تصل أحداث
`sms_message_received` و`sms_message_status_changed` موقعة بسر Webhook الخاص
بحساب Wa. يُعاد التسليم تلقائيًا عند انقطاع الشبكة أو رد HTTP غير ناجح؛ لذلك يجب
على المستلم معالجة الحدث مرة واحدة بالاعتماد على قيمة `X-Savana-Delivery-Id`
الثابتة في جميع محاولات الحدث نفسه. التوقيع الحديث في `X-Savana-Signature` هو
`v1=HMAC_SHA256(secret, delivery_id + "." + raw_body)`؛ ويبقى `X-Signature`
بتوقيع `sha256=HMAC_SHA256(secret, raw_body)` مؤقتًا للتوافق. يجب اعتماد التوقيع
الحديث عند أي تكامل جديد.

إذا تعذر الجزم بوصول طلب الإرسال، يعيد Wa الحقل `retry_same_request=true`؛ يجب
حينها إعادة الطلب نفسه وبنفس `Idempotency-Key`. أما الخطأ الحتمي فيستلزم مفتاحًا
جديدًا بعد تصحيح المدخلات.

أما عملاء SMS Gateway الحاليون فيستمرون باستعمال مساراتهم الحالية، سواء واجهة
`/services/*.php` القديمة أو `/services/v1`، وبمفتاحهم الحالي مباشرة. لا يلزم سوى
تغيير اسم النطاق الرئيسي عند الحاجة؛ ولا يتغير payload أو المصادقة أو الاستجابة.

## API المباشر لـSMS Gateway

تعرض صفحة «حسابات SMS» زر «API والربط» لكل حساب يملكه الـTenant. لا يعيد endpoint
الخاص بقائمة الحسابات أي سر؛ عند الضغط فقط يستعمل Wa اعتماد الربط الداخلي ليسترجع
`User.apiKey` الحالي من Gateway، ثم يعيده مع `Cache-Control: no-store`. يتطلب الكشف
`account_id` صريحًا ومملوكًا للـTenant، ولا يوجد أي حساب افتراضي مشترك.

يبقى عقد العملاء القديم كما هو، ويمكن استعمال POST بدل وضع المفتاح أو الرسالة في
عنوان URL:

```http
POST https://sms-gateway.savana.ly/services/send.php
Content-Type: application/x-www-form-urlencoded

key=<sms-gateway-account-api-key>&number=218912345678&message=Hello&option=1
```

المفتاح المعروض هو مفتاح حساب العميل العام نفسه، وليس اعتماد Wa الداخلي. لذلك لا
تتغير مسارات التكاملات الحالية أو حقولها أو استجاباتها، ويكفي تبديل النطاق الرئيسي
عند نقل تكامل قائم. تغلق الواجهة المفتاح من الذاكرة عند إغلاق نافذة الربط، ولا
تضعه في query أو logs عند استرجاعه من Gateway.

## الإحصاءات

تعرض بوابة Wa إجماليات الانتظار والإرسال والتسليم والفشل والإلغاء والوارد لكل حساب
أو لجميع الحسابات، للفترات اليوم و7 و30 يومًا أو فترة مخصصة. المصدر المرجعي هو
SMS Gateway؛ وإذا تعذر حساب واحد توضح الواجهة أن النتيجة جزئية بدل عرضه كصفر.

## دورة USSD

توجد وحدة USSD في `/portal/ussd` وتعمل مع أي حساب SMS مفعّل:

1. يختار المستأجر حساب SMS واحدًا؛ ويستخدم الحساب المُدار الجهاز والشريحة اللذين
   عينتهما الإدارة دون إظهار معرّفاتهما التقنية. الحساب اليدوي الطارئ فقط يسمح
   باختيار الجهاز والشريحة من Wa.
2. يحجز Wa Savana تكلفة `sms.ussd` بمفتاح منع تكرار معزول للحساب.
3. تقبل بوابة SMS الطلب بحالة `pending` ويرجع Wa Savana استجابة `202`.
4. ينفذ الهاتف الرمز ثم تعيد البوابة النتيجة عبر الحدث الموقع `ussd.response.v1`.
5. يحدث سجل Wa Savana تلقائيًا، مع استطلاع كل خمس ثوانٍ وزر تحديث يدوي كمسار بديل.

يحفظ السجل باستخدام `tenant_id + sms_account_id + gateway_ussd_id`. وبذلك يدعم
Tenant واحد عدة حسابات SMS حتى عند تكرار معرّفات USSD بينها. لا يعني قبول الطلب
أن النتيجة وصلت؛ الحالة `completed` لا تظهر إلا بعد استجابة الهاتف.

## التشغيل والمراقبة

- حالة `active` تعني نجاح health check؛ الحسابات الأخرى لا تستخدم للإرسال.
- تعطيل الحساب يحافظ على السجل ويوقف Webhook البعيد بأفضل محاولة ممكنة.
- إذا عُطل الحساب الافتراضي يختار النظام حسابًا مفعّلًا بديلًا.
- راقب `sms_gateway_accounts.last_error` والأحداث ذات أخطاء التوقيع أو معدل الطلبات.
- راقب `last_history_sync_at` و`last_history_error` حتى تكتمل مطابقة السجل.
- راقب طلبات `sms_ussd_requests.status='pending'` القديمة واتصال هاتف Android.
- راقب `tenant_api_callback_outbox`: الانتقالات إلى `dead_letter` تسجل كخطأ مع
  عدد المتأخرات وأقدم حدث. بعد إصلاح endpoint الخاص بالعميل، أعد حدثًا محددًا إلى
  `failed` مع `attempts=0` و`available_at` للحظة الحالية من خلال إجراء تشغيلي
  موثق وبعد أخذ نسخة من SQLite؛ لا تحذف الصف كي يبقى `delivery_id` ثابتًا.
- يحتفظ النظام بنتائج منع تكرار SMS API لمدة 90 يومًا، وبـcallbacks الناجحة 30
  يومًا، وبـdead letters لمدة 180 يومًا. لا يحذف التنظيف أي حدث pending أو failed
  قابل لإعادة المحاولة أو processing.
- يجب أن تكون ساعة النظام متزامنة؛ الحد الأقصى لانحراف توقيع Webhook خمس دقائق.

الرجوع إلى صورة أقدم بعد تطبيق migration 052 ليس رجوع صورة فقط: يلزم استعادة نسخة
SQLite السابقة، كما يلزم عند اعتماد مفاتيح Gateway مُدارة إعادة قاعدة Gateway
وصورتها بصورة منسقة. المسار المفضل بعد التهيئة هو forward-fix؛ وأي rollback يجب
أن يعيد الخدمتين وقاعدتيهما معًا حتى لا تتعطل المفاتيح الحالية.
