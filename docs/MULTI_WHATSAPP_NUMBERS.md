# دعم عدة أرقام WhatsApp للحساب

أصبح كل حساب مستأجر قادرًا على امتلاك عدة أرقام WhatsApp Business. يحتفظ جدول `tenants` ببيانات الرقم الافتراضي فقط للتوافق الخلفي، بينما المصدر الفعلي للأرقام هو `tenant_whatsapp_numbers`.

## السلوك

- يضيف Embedded Signup جميع الأرقام المصرّح بها في WABA، حتى 1000 رقم عبر صفحات Graph API.
- لا يمكن ربط `phone_number_id` بأكثر من مستأجر واحد.
- كل طلب يحدد الرقم عبر الترويسة `X-WhatsApp-Phone-Number-Id`، أو `phone_number_id` في body/query للتكاملات غير المتصفحية.
- عند عدم تحديد رقم، يُستخدم الرقم الافتراضي.
- تُرفض أي محاولة لاستخدام رقم غير مملوك للمستأجر بدل الرجوع بصمت إلى الرقم الافتراضي.
- الرسائل والمحادثات وحالة القراءة ونافذة خدمة الـ24 ساعة معزولة حسب الرقم.
- عمليات الإرسال والوسائط والبث وQR والملف التجاري والقوالب على Meta تستخدم توكن وWABA الخاصين بالرقم المختار.
- إعداد Dataset وسجل WhatsApp Business Messaging Events معزولان حسب الرقم المختار.
- إحصاءات WhatsApp في بوابة المستأجر تتبع الرقم المختار، بينما تبقى الفوترة على مستوى الحساب.

## واجهات الإدارة

بوابة المستأجر:

- `GET /portal/whatsapp/numbers`
- `PATCH /portal/whatsapp/numbers/:phoneNumberId`
- `POST /portal/whatsapp/numbers/:phoneNumberId/default`
- `DELETE /portal/whatsapp/numbers/:phoneNumberId`
- `POST /portal/whatsapp/connect` يستورد أو يزامن أرقام WABA المصرح بها.

واجهة المدير:

- `GET /tenants/:id/whatsapp-numbers`
- `POST /tenants/:id/whatsapp-numbers`
- `POST /tenants/:id/whatsapp-numbers/:phoneNumberId/default`

External API v1:

- `GET /v1/whatsapp/numbers`
- أرسل `X-WhatsApp-Phone-Number-Id` مع طلبات الرسائل والاستعلامات.

لا تعيد أي من واجهات القوائم توكنات الوصول المشفرة أو الصريحة.

## ترحيل الإنتاج

الترحيلان `045_multi_whatsapp_numbers.sql` و`046_whatsapp_number_scoped_conversions.sql` إضافيان وآليان:

1. ينشئ سجل الأرقام وفهرسًا يضمن رقمًا افتراضيًا واحدًا لكل مستأجر.
2. ينقل رقم كل مستأجر حالي إلى السجل بوصفه الرقم الافتراضي.
3. ينشئ نوافذ محادثة منفصلة لكل رقم، ويهيئها من بيانات جهات الاتصال الحالية.
4. ينقل إعداد Dataset وأحداث التحويل القديمة إلى الرقم الافتراضي، ثم يعزل الأحداث الجديدة حسب الرقم.
5. يبقي الحقول القديمة على `tenants` متزامنة مع الرقم الافتراضي لتشغيل إصدار سابق من الخادم عند الحاجة.

خطوات النشر المقترحة:

1. أنشئ نسخة احتياطية موثقة: `cd server && npm run backup`.
2. انشر الخادم والواجهة معًا. يطبق الخادم الترحيل قبل فتح منفذ HTTP.
3. تحقق أن `GET /health` يعيد `status: ok` و`migrations.pending: 0`.
4. افحص أن الحساب القديم يعرض رقمه الحالي كافتراضي.
5. اربط WABA تجريبيًا يحتوي رقمين، ثم اختبر الإرسال والاستقبال وتبديل الرقم.
6. راقب أخطاء webhook وMeta وسجل النشاط بعد النشر.

الرجوع الطارئ آمن على مستوى التطبيق لأن الحقول القديمة ما زالت موجودة ومزامنة. إذا لزم الرجوع عن البيانات نفسها، أوقف الكتابة واستعد نسخة SQLite المأخوذة قبل النشر باستخدام إجراءات النسخ الاحتياطي الموثقة في `server/scripts/README.md`.

## فحوص الإصدار

```bash
cd server && npm test
cd ../client && npm run lint && npm run build
```

تغطي الاختبارات ملكية الرقم، عزل المستأجر، تبديل الرقم الافتراضي، استيراد عدة أرقام من WABA، ترحيل البيانات، وعزل نافذة الـ24 ساعة وDataset وأحداث التحويل لكل رقم.
