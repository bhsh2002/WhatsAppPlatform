# تشغيل حسابات SMS المتعددة

يدعم كل Tenant في Wa Savana عدة حسابات SMS. المفتاح التشغيلي للمحادثة هو:

```text
tenant_id + sms_account_id + contact_number
```

لذلك يمكن لبوابتين إرجاع `message_id` نفسه دون اختلاط، كما لا يمكن لـWebhook
الخاص بحساب تحديث رسائل حساب آخر.

## الإعداد

اضبط في بيئة خادم Wa Savana:

```dotenv
SMS_GATEWAY_CALLBACK_BASE_URL=https://wa.example.com/api/integrations/sms-gateway/events
SMS_WEBHOOK_RATE_LIMIT_PER_MINUTE=1200
```

ثم افتح `/portal/integrations/sms` وأضف كل حساب على حدة. بيانات كل حساب هي:

- اسم فريد داخل الـTenant.
- رابط SMS Gateway عام وآمن.
- مفتاح API مستقل، يخزن مشفرًا بـ`CRYPTO_KEY`.
- أجهزة افتراضية اختيارية ومنفذ SIM اختياري عند تحديد جهاز واحد.
- حالة التفعيل وعلامة الحساب الافتراضي.

إن لم يحدد المرسل `sms_account_id` يستخدم الحساب الافتراضي. الرد من محادثة SMS
يستخدم دائمًا الحساب الذي استقبل المحادثة، ولا ينتقل تلقائيًا إلى حساب آخر.

## دورة الرسالة

1. يحجز Wa Savana تكلفة `sms.text` بمفتاح منع تكرار.
2. يرسل الطلب إلى حساب SMS المختار عبر HTTPS بعد التحقق من DNS وتثبيت عنوان IP.
3. عند قبول البوابة يثبت الخصم ويحفظ الرسالة باسم الحساب.
4. تستقبل حالات الإرسال والرسائل الواردة عبر Webhook موقع لكل حساب.
5. يحدث الصندوق الموحد مباشرة عبر SSE، مع منع تكرار `delivery_id`.

## التشغيل والمراقبة

- حالة `active` تعني نجاح health check؛ الحسابات الأخرى لا تستخدم للإرسال.
- تعطيل الحساب يحافظ على السجل ويوقف Webhook البعيد بأفضل محاولة ممكنة.
- إذا عُطل الحساب الافتراضي يختار النظام حسابًا مفعّلًا بديلًا.
- راقب `sms_gateway_accounts.last_error` والأحداث ذات أخطاء التوقيع أو معدل الطلبات.
- يجب أن تكون ساعة النظام متزامنة؛ الحد الأقصى لانحراف توقيع Webhook خمس دقائق.
